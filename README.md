# Defect Management System — Home

ระบบส่งรูปและติดตาม Defect: ผู้ตรวจเปิดงาน → ผู้รับผิดชอบแก้ไขและส่งรูปหลังแก้ → ผู้ตรวจตรวจรับ / ตีกลับ
ถ้าเลยกำหนดแล้วยังไม่ได้ส่งงาน ระบบจะออก NCR ให้อัตโนมัติและแจ้งเตือนบนเว็บ (กระดิ่ง) — ไม่ส่งอีเมลแจ้งเตือน

## เริ่มใช้งาน

Docker ใช้เฉพาะ **MySQL + phpMyAdmin** ตัวโปรแกรมรันบนเครื่องด้วย Python 3.12

1. เปิด Docker Desktop
2. ดับเบิลคลิก **`run.bat`** (ครั้งแรกจะสร้าง `.venv` และติดตั้ง packages ให้เอง)
   - หรือรันเองใน cmd: `docker compose up -d` แล้ว `.venv\Scripts\python wsgi.py`
3. ปิดโปรแกรม: กด Ctrl+C ในหน้าต่าง (ฐานข้อมูลใน Docker ยังรันต่อ ปิดด้วย `docker compose stop`)

| บริการ | ที่อยู่ |
|---|---|
| ระบบ Defect | http://localhost:5100 |
| phpMyAdmin | http://localhost:8181 (user/pass ตาม `MYSQL_USER` / `MYSQL_PASSWORD` ใน .env) |
| MySQL | localhost:3307 |

รูปภาพที่อัปโหลดเก็บในโฟลเดอร์ `uploads\` ข้างโปรแกรม (สำรองโฟลเดอร์นี้คู่กับฐานข้อมูล)

ให้มือถือในวง Wi-Fi เดียวกันใช้: เปิด `http://<IP เครื่องนี้>:5100` (ครั้งแรก Windows อาจถามให้อนุญาต Firewall สำหรับ Python ให้กด Allow) และตั้ง `APP_BASE_URL` ใน .env เป็นที่อยู่เดียวกัน

> การเปิดกล้องจากหน้าเว็บบน iPhone/Android บางรุ่นต้องใช้ HTTPS ถ้าเปิดผ่าน IP ธรรมดาแล้วกด "ถ่ายรูป" ไม่ขึ้นกล้อง ปุ่ม "เลือกจากคลัง" ยังใช้ได้เสมอ และเมนูของมือถือมีตัวเลือกถ่ายรูปให้ด้วย

## บัญชีผู้ใช้

- **Admin**: ชื่อผู้ใช้ `ADM` รหัสผ่านตาม `ADMIN_PASSWORD` ใน .env (ค่าเริ่มต้น `Test*123`) ไม่ต้องตั้งรหัสใหม่
- Admin สร้างผู้ใช้ด้วยชื่อ **ตัวพิมพ์ใหญ่ภาษาอังกฤษ 3 ตัว** เลือกประเภท *ผู้ตรวจ* หรือ *ผู้รับผิดชอบแก้ไข*
- ผู้ใช้ใหม่เข้าครั้งแรกด้วยรหัสกลาง `DEFAULT_PASSWORD` (ค่าเริ่มต้น `Test*123`) แล้วระบบบังคับตั้งรหัสใหม่: อย่างน้อย 8 ตัว มีตัวพิมพ์ใหญ่ ≥1 ตัวเลข ≥1 และอักขระพิเศษ ≥1
- ปุ่ม **รีเซ็ตรหัส** ในหน้า ผู้ใช้งาน คืนรหัสเป็นรหัสกลางและบังคับตั้งใหม่อีกครั้ง
- หน้า **จับคู่ผู้ตรวจ**: ผู้ตรวจมอบงานได้เฉพาะผู้รับผิดชอบที่ติ๊กไว้

## กฎของระบบ

| เหตุการณ์ | ผลลัพธ์ |
|---|---|
| ผู้ตรวจเปิด Defect | เลขที่ `DEF-ปีพ.ศ.-00001` แจ้งผู้รับผิดชอบ |
| 1 วันก่อนครบกำหนด / วันครบกำหนด | เตือนผู้รับผิดชอบ |
| เลยวันกำหนด และยังไม่ส่งงาน (รอแก้ไข / ตีกลับ) | ออก `NCR-ปีพ.ศ.-0001` แจ้งผู้ตรวจและผู้รับผิดชอบ (ตรวจทุก `CHECK_INTERVAL_MINUTES` นาที) |
| ส่งงานก่อนกำหนดแล้วผู้ตรวจยังไม่ได้ตรวจ | ไม่ออก NCR |
| ผู้ตรวจตีกลับหลังเลยกำหนด | ออก NCR ทันที |
| ผู้ตรวจตรวจรับ | ปิด Defect และปิด NCR (ถ้ามี) |

## อีเมล (Gmail)

การแจ้งเตือนทุกอย่างแสดงบนเว็บ (กระดิ่ง) เท่านั้น อีเมลใช้เฉพาะเมนู **ส่งอีเมลรายงาน** ถ้าต้องการใช้ ให้ตั้ง Gmail ใน .env:

```
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_TLS=1
SMTP_USER=บัญชี@gmail.com
SMTP_PASSWORD=App Password 16 ตัว (Google Account → Security → App passwords)
SMTP_FROM=Defect System <บัญชี@gmail.com>
```

แล้วปิด-เปิดโปรแกรมใหม่

## AI ตรวจรูป (Gemini) — ไม่บังคับ

ให้ AI เทียบรูปก่อนแก้กับรูปหลังแก้ แล้วให้ความเห็นว่า **ดูเรียบร้อย / น่าจะยังไม่เสร็จ / ไม่แน่ใจ** โดยอ้างอิงเคสเก่าในระบบที่คล้ายกัน (ที่ผู้ตรวจเคยตรวจรับหรือตีกลับ พร้อมเหตุผล) ความเห็น AI ใช้ประกอบเท่านั้น ไม่เปลี่ยนสถานะงาน ไม่กระทบ NCR

1. ขอ API key ที่ https://aistudio.google.com/apikey
2. ใส่ใน .env แล้วปิด-เปิดโปรแกรมใหม่
   ```
   GEMINI_API_KEY=key-ที่ได้
   GEMINI_MODEL=gemini-2.5-flash
   GEMINI_EMBED_MODEL=gemini-embedding-001
   ```
3. Admin เข้าเมนู **คลังเคส AI** → กด **สร้างคลังเคสย้อนหลัง** ครั้งแรกครั้งเดียว (งานที่ตรวจหลังจากนี้เข้าคลังเอง)
4. ในหน้า Defect สถานะ "รอตรวจรับ" ผู้ตรวจของงานนั้น (และ Admin) จะเห็นปุ่ม **ให้ AI ตรวจรูป** — ผู้รับผิดชอบไม่เห็นปุ่มและไม่เห็นผล AI

- เว้น `GEMINI_API_KEY` ว่าง = ปิด AI ระบบทำงานเหมือนเดิมทุกอย่าง
- รูปจะถูกส่งไป Google: key แบบฟรี Google อาจนำข้อมูลไปใช้ปรับปรุงโมเดล ถ้ารูปงานเป็นความลับให้ใช้ key แบบเสียเงิน (เปิด billing)
- มีค่าใช้จ่ายเฉพาะตอนกดปุ่ม และตอนเก็บเคสเข้าคลัง (ครั้งละไม่กี่สตางค์)

## ข้อมูลตัวอย่าง (เพื่อทดลองเท่านั้น — เข้าฐานข้อมูลจริง)


สร้างผู้ตรวจ INA, INB และผู้รับผิดชอบ CTA–CTD (รหัส `Demo#1234`) พร้อม Defect ตัวอย่าง 46 รายการ

## สำรองข้อมูล

- ฐานข้อมูล: phpMyAdmin → Export หรือ `docker compose exec db mysqldump -u root -p defect_db > backup.sql`
- รูปภาพ: คัดลอกโฟลเดอร์ `uploads\`

## พัฒนา / ทดสอบบนเครื่อง (ไม่ใช้ Docker)

```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt pytest
.venv\Scripts\python -m pytest -q          # ทดสอบเส้นทางหลักทั้งหมด
# ทดสอบกับ MySQL: ตั้ง TEST_DATABASE_URL=mysql+pymysql://user:pass@127.0.0.1:3307/defect_test
# ถ้าไม่มี MYSQL_* / DATABASE_URL ใน .env โปรแกรมจะใช้ SQLite (dev.db) แทน
```
